# Project Management eGLV App Skill

## Mission

Manage the eGLV Business Development Agent App as a product-development project with a clear demo path, controlled scope, and traceable decisions. Prioritize what proves the service value: configurable Stage-Gate workflow, project transparency, gate decisions, and agent-assisted time savings.

## Workstreams

- Product: MVP scope, user stories, acceptance criteria, demo story.
- Frontend: dashboard, project detail, gate review, settings, agent panel.
- Backend/API: process definitions, projects, evidence, gate reviews, agent runs.
- Content: Pflanzenkohle/Pyrolyse seed data, gate criteria, business-case examples.
- Deployment: demo link, seed reset, no confidential data.
- Video/Pitch: service blueprint graphic and Stage-Gate-agent flow graphic.

## MVP Acceptance Criteria

- A viewer understands the eGLV process within two minutes.
- A demo project visibly moves through stages and gates.
- Missing evidence is visible.
- A gate decision can be prepared and recorded.
- Stages and gates can be edited in settings.
- The agent demonstrably reduces manual preparation work.

## Risk Register

- Scope creep: too many screens before the core flow works.
- Security ambiguity: demo link used with real data.
- Agent overclaiming: generated text perceived as management decision.
- Process rigidity: stages and gates hard-coded in UI or backend.
- Weak story: app looks like a generic project dashboard instead of eGLV Business Development.

## Delivery Sequence

1. Confirm MVP screens and demo story.
2. Define seed data for Pflanzenkohle/Pyrolyse.
3. Build API schema and mock data.
4. Implement dashboard and project detail.
5. Implement gate review and settings.
6. Add agent panel and demo outputs.
7. Deploy demo link.
8. Produce two video graphics and final walkthrough script.

## Communication Rule

Always separate demo capability from production capability. The demo proves usefulness; production requires security, governance, integrations, and operating model.
